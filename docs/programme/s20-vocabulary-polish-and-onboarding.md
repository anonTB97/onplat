## Summary

Slice 1 gave the product yard words for the four authorization states, a Legend, a status strip and a first-run strip; S10–S13 and S11 then added five screens (Tomorrow, Week Ahead, the schedule door, the runs table, the field map) each with its own words, its own pill styles and its own amber block. Read at head, the shell draws a state badge **twenty-four different ways** (`fontSize: 9.5, fontWeight: 700 …` inline in 24 files; `badgeStyle` is imported by two), keeps **six private copies** of the red/amber/green/grey palette (`TomorrowBoard.tsx:54-57`, `WeekAhead.tsx:40-44`, `IssuesBoard.tsx:41-75`, `LedgerBoard.tsx:22-48`, `Proposals.tsx:26-31`, `SourceCard.tsx:83`), and shows engine codes raw on the demo's own path: the trace panel reads `SUSPEND R07 1 hop … via electrical_bus … Cleared by isolation_authority … rule version 0000…`, the inspector and the job card `.replace(/_/g, " ")` the authority by hand in four places, the cascade card prints `3-148-2-E ⟶ 3-172-1-E · electrical_bus`, and the ledger styles three of the fourteen actions the server writes — `HAZARD_CLEARED`, `DOCUMENT_REPLACED` and `SCHEDULE_CHANGE_PROPOSED` fall through to a grey pill wearing their `UPPER_SNAKE` name. Twenty-five `setError(String(e))` sites print `Register unavailable (Error: GET …/activities → 503)` because `String(new Error())` keeps the `Error:` prefix that `theme.ts::errText` was written to strip and only two files import. The Legend stops at slice 1's five groups: none of Tomorrow's, Week Ahead's, the documents' or the ledger's words is in it. The first-run strip is one generic set of three cards, shown identically on every module, dismissed once for all. The Daily Ops print is a second, unrelated stylesheet beside `reports.ts::toPrintHtml`. And the manual start date on the inspector's *Propose to P6* is parsed as `T06:00:00Z` — the one hard-coded Z left after S10, on the Planner's demo step.

This slice does the pass **mechanically**: four small primitives and one table, then a prioritised list where every row names a file, an element, what it says now, what it says after, and the rule it breaks. `words.ts` is the single table of display names for every code the server serves (authorities, couplings, hazard kinds, rule codes, document kinds and statuses, issue kinds, proposal statuses, ledger actions, the Tomorrow/Week/shift words) and the `LEGEND` the drawer renders from it; `Badge.tsx` is the one pill, `Trace.tsx` the one trace sentence with *engine detail* behind a fold, `Notice.tsx` the one amber/red block and the one *X unavailable* line; `firstRun.ts` gives each of the demo's twelve role-screen pairs its own three cards. `docs/training-guide.md` is the role cards the playbook's M10 sign-off asks for: seven roles, five tasks each, in the product's own words, each ending on a named screen or sheet.

**Decisions the builder does not revisit:** no new dependency (a vocabulary table and four components are ~400 owned lines); `theme.ts` keeps the palettes and gains `TONES`, `words.ts` holds words only, so a colour change and a word change are different commits; the engine's codes stay visible **behind the fold and in tooltips**, never removed (the API and the trace must still agree with the screen, `theme.ts:7-9`); the authority table is a display map — an unknown code passes through humanised (`_` → space), never throws, and a test lists the codes the engine emits today so a new one is a red test, not a raw word; the Legend is one drawer driven by `LEGEND`, and a vitest asserts every `Badge` word in the tree has a Legend entry; first-run cards are per (role, module) and per browser, with a *Show the cards again* in the role menu; the Daily Ops print is deleted in favour of the shift sheet (R1 already exists in Reports — two prints of the same board is the inconsistency); `words.mjs` (S17) is edited in the same commit as any label it quotes; rule names come from a static copy of `handoff/01-rule-table.csv`'s *Name* column with S14's served `rule-table` overriding it when loaded (cut line); `data-testid` is not added anywhere.
