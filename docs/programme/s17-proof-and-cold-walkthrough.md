## Summary

Every check that exists today proves the demo world or one route: the API suites run on the in-memory store, nothing drives the shell but a person, the four documents a newcomer reads first (README status, `docs/BACKLOG.md`, the engine's `lib.rs`, ADR 0002) describe a milestone that is three quarters of a year behind the code, and `handlers.rs` is 4,349 lines with eleven features in it. Nobody who was not in the room has ever run the product from the README.

This slice makes the pilot's path **something a machine walks every push and a stranger walks once**. A **Playwright smoke** (`shell-web/e2e/smoke.mjs`, `playwright-core` only, plain `node`) boots nothing itself; `scripts/smoke.sh` builds the release binary and the shell, serves the built shell **through the API's own static fallback** on the reference hull, and the smoke drives the demo script's morning role by role — status strip, every role's landing screen, the trace of a held space, a clearance with its basis then the scrub back that shows the hold still there, a field condition raised from the log, a refusal proposed to P6 and the change-request CSV read back, the zone in focus with next door, the print sheet, the yard-clock door's dry run → commit → revert → restore, the API cut off at the wire and every board reading *unavailable*, and the ledger's chain verify at the end — one screenshot per step into an artifacts directory CI uploads beside S16's evidence. The **five pilot-critical behaviours** (plus the sixth the ISSO added, a person on every ledger row) are pinned in one file over `support::reference_hull()`, so the same six tests run on memory every push and on PostgreSQL in `production-path`. `handlers.rs` is **split by feature** into eleven modules by a mechanical procedure whose proof is that `routes.rs`, the generated leak tests, the SSP and every existing test file are byte-identical across the split, plus one new test that drives every inventory row through the router. The **documents are reconciled** to the code as a list of concrete edits, not a rewrite. The **3,000-space measurement** is taken with the hull generator at scale and a release build, and written into `docs/stress-test.md` in the same table shape as the 40k-activity run. And a **cold walkthrough** protocol sends a fresh agent with only `README.md` and `docs/demo-script.md` through the product, filing every stop in `docs/programme/cold-walkthrough.md`.

**Decisions the builder does not revisit:** `playwright-core@1.49.1` is an exact-pinned **devDependency** (dev and CI only; never in the binary; the runtime tree stays react + react-dom) and `@playwright/test` is not added — a runner is a hundred lines and a second framework is a second thing to accredit; the smoke is run by `node`, not vitest; the shell under test is `shell-web/dist` served by `serve` with `WADL_STATIC_DIR` (one origin, the deployed shape; vite is not in the loop); selectors are the shell's **yard words**, every string held in `shell-web/e2e/words.mjs` with its `file:line`, and **no `data-testid` is added** to any shell file (S20 renames labels in one file, not two); "the API killed" is `page.route('**/api/**', abort)` — what a dead API looks like to the shell, without killing the process that serves the shell; screenshots are viewport captures at 1600×900; the smoke runs on the in-memory store on every push in its own job, and the PostgreSQL run is one extra step in `production-path` behind the cut line; the six pins live in `crates/wadl-api/tests/pilot_pins.rs` and are never `#[ignore]`d — they choose the store at runtime like S16's suites; `handlers.rs` **keeps its name and becomes the shared kernel** (`read_import_body`, `body_rejection`, `AsOf`, `DryRun`, `ledger_document`, `decide`), so every `use crate::handlers::{…}` in the door modules keeps compiling; the eleven module names below are final; `routes.rs` is not edited by the split; the scale run is local and recorded, not a CI job; the cold walkthrough is a separate session with no memory of this one.

### The cold walkthrough (`docs/programme/cold-walkthrough.md`)

**Protocol.** A **fresh session** (no memory of this one; not the S17 builder) is given exactly this: the repository path, "read `README.md` and `docs/demo-script.md`; do what they say, in order; you may run shell commands and drive the browser with Playwright as the README's tooling describes; you may **not** open any other file — not `docs/`, not `crates/`, not `shell-web/src` — and not ask anyone; every time you cannot proceed, or the screen disagrees with the words, or you had to guess, stop and file it; ninety minutes; write your record to `docs/programme/cold-walkthrough.md` in the template already there, commit that one file." The S17 builder spawns it after sitting A has landed (the smoke pins the path first, so a stop is a document's fault or a real defect, never an unknown).

**Record template** (in the file before the run): header (date, session, commit, host, minutes used); then a table `| # | Where (file:line or screen) | The document says | What happened | Class | Owner |` with classes **blocker** (could not continue), **wrong** (the screen contradicts the words), **unclear** (had to guess and guessed right), **cosmetic**; owners **S17-doc** (fixed in this slice: README, demo script, Field Guide wording), **S20** (vocabulary/polish list), **defect** (a product bug → `docs/execution-plan.md` Deferred or a new row), **yard** (needs the yard's answer). A closing line: *reached the end of the demo script: yes/no; steps completed N of 6 sections; first-run impression in one paragraph.* Then the S17 builder's **triage** under the table: each row's disposition and commit. **Pass criterion**: zero blocker-class stops on the second run (run again after the doc fixes, same protocol, a new fresh session) — recorded as run 2 in the same file.
